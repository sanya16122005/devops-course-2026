# Мой пет-проект

Идея: сайт-визитка (портфолио) — одностраничный сайт с моими проектами,
навыками и контактами. Хочу довести его до состояния, когда он автоматически
пересобирается и деплоится при каждом пуше в main.

Стек: HTML / CSS / JavaScript, хостинг на GitHub Pages, сборка через GitHub Actions.

Цель: научиться настраивать автоматический деплой статического сайта из репозитория —
то есть пройти полный путь от коммита до продакшена своими руками.

## Что будет на сайте

- **Главный экран** — имя, короткое описание («студент 3 курса, изучаю DevOps»), фото.
- **Навыки** — список технологий с уровнем владения: Git, Linux, Docker, Python, JavaScript.
- **Проекты** — карточки учебных проектов (React-таймер, FastAPI-сервис и др.)
  со ссылками на репозитории GitHub.
- **Контакты** — GitHub, Telegram, почта.
- **Тёмная и светлая тема** с переключателем, адаптивная вёрстка под телефон.

## Как будет устроен деплой

1. Код сайта лежит в отдельном репозитории.
2. Новые разделы делаю в feature-ветках и вливаю через Pull Request (GitHub Flow).
3. На каждый PR GitHub Actions запускает проверки: валидацию HTML и линтер CSS/JS.
4. После merge в main workflow автоматически публикует сайт на GitHub Pages.

## Сроки реализации

| Этап | Что делаю | Срок |
|---|---|---|
| 1 | Вёрстка главного экрана и раздела «Навыки» | до конца сентября |
| 2 | Раздел «Проекты», контакты, адаптив | октябрь |
| 3 | Публикация на GitHub Pages вручную | начало ноября |
| 4 | CI: проверки на каждый Pull Request | ноябрь (после занятий по CI/CD) |
| 5 | CD: автодеплой при merge в main | декабрь |

## Что будет считаться готовым результатом

Сайт открывается по публичной ссылке, а любое изменение, влитое в main,
само появляется на сайте в течение пары минут — без ручных действий.
