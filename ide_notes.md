# Git в VS Code vs терминал

## Три вещи, которые удобнее в VS Code

1. **Просмотр diff'а перед коммитом.** Клик по файлу в панели Source Control открывает
   два окна бок о бок: слева версия из последнего коммита, справа текущая. Изменённые
   строки подсвечены, видно каждый символ. В терминале `git diff` печатает то же самое
   текстом, но на большом файле это тяжело читать.

2. **Постадийное добавление изменений (stage по строкам).** Можно выделить в diff'е
   несколько конкретных строк и нажать «Stage Selected Ranges» — в коммит попадёт
   только этот кусок файла. В терминале для этого нужен `git add -p` с интерактивным
   разбором каждого «ханка».

3. **Разрешение merge-конфликтов.** Встроенный редактор конфликтов показывает три
   панели — Current, Incoming и Result — с кнопками «Accept Current / Incoming / Both».
   В терминале приходится вручную вычищать маркеры `<<<<<<<`, `=======`, `>>>>>>>`,
   и легко случайно оставить один из них в коде.

Отдельно стоит упомянуть **GitLens**: он показывает прямо в конце строки, кто и когда её
менял и в каком коммите — визуальный `git blame` без отдельной команды.

## Одна вещь, которую удобнее делать в терминале

**Интерактивный rebase (`git rebase -i HEAD~3`) и вообще любая работа с историей.**
В терминале ты явно видишь список коммитов и сам пишешь напротив каждого `pick`,
`squash`, `reword` или `drop` — полный контроль над тем, что произойдёт. UI такие
операции либо прячет, либо выполняет «магически», и когда что-то пойдёт не так,
чинить всё равно придётся через `git reflog` в терминале. Плюс терминальные команды
скриптуются и работают на сервере по SSH, где никакого VS Code нет.
